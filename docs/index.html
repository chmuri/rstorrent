Technology & Performance

Next-Generation BitTorrent Architecture

Built from scratch in Rust to eliminate the legacy bugs of historical clients: memory leaks, I/O thread stalls, and crashes under heavy multithreaded load.

⚡

Tokio Async & Zero-Segfault

Multithreaded Tokio async runtime with non-blocking positional disk I/O. Full memory safety and resilience to malformed network buffers.

🧩

SIMD Rarest-First & Dynamic Endgame

O(N/64) bitfield operations using hardware POPCNT/CLZ instructions. Peer speed classification, rarest-first piece priority, and instant global CANCEL broadcast in endgame mode.

🌊

Zero-Copy BufferPool & BDP Tuning

Lock-free 16 KiB buffer arena via crossbeam-queue, zero-copy Bencode parsing, and adaptive request queue depth (Q 4..512) tuned to peer RTT and bandwidth.

🛡️

Multithreaded Piece Hashing (Rayon)

Offloaded SHA-1 and BitTorrent v2 SHA-256 Merkle tree hashing to Rayon thread pool, preventing disk validation from starving Tokio executor threads.

🔌

SCGI, XML-RPC & JSON-RPC

Complete SCGI protocol compatibility over UNIX sockets or TCP. Seamless integration with ruTorrent, Flood, pyrosimple, and existing rTorrent tooling.

📡

Native gRPC & Terminal TUI

High-performance Tonic rtorrent.v1 gRPC API with telemetry streaming, paired with an interactive terminal TUI (Ratatui/Crossterm) and remote rtorrent-tui client.

🌐

BitTorrent v1 & v2 (BEP Suite)

Full support for Kademlia DHT (IPv4/IPv6 BEP 5/32), PEX (BEP 11), Fast Extension (BEP 6), uTP with LEDBAT (BEP 29), MSE/PE encryption, and BitTorrent v2 (BEP 52).

💻

Embedded Web UI (Leptos / Wasm)

Opt-in Axum REST + WebSocket server with an embedded single-page app written in Rust (Leptos WebAssembly), Bearer token auth, and real-time node inspection.

Dataflow & Torrent Lifecycle

Strict non-blocking pipeline: network I/O driven by Tokio async reactor while disk operations and hashing run on isolated worker pools.

STAGE 01 // METADATA
Parsing & Construction
Zero-copy Bencode parser converts .torrent or magnet metadata into session objects without unnecessary allocations.
STAGE 02 // SWARM PEERING
Discovery & Handshake
Reactor announces to HTTP/UDP trackers while DHT queries Kademlia to assemble an active peer connection pool.
STAGE 03 // BDP PIPELINING
Rarest-First Transfer
SIMD bitfield selects rarest chunks, dynamically pipelining requests (Q 4..512) tuned to peer RTT and bandwidth.
STAGE 04 // RAYON HASHING
Validation & Storage
Completed chunk verified by Rayon worker pool then written to disk via positional non-blocking I/O.

Core Architectural Invariants

Async Network Reactor + Isolated Disk Pool
Tokio reactor handles P2P sockets, DHT queries, and tracker announces without blocking. File I/O and SHA-1/256 hashing run on Rayon threadpools so reactors never stall.
Compiler-Enforced Safety Boundaries
Strict unsafe_code = deny enforced on all higher crates. Unsafe is strictly isolated to system primitives in lt-sys and safe mmap wrappers.
Byte-Oriented Binary Bencode Model
Bencode keys and values are parsed into zero-copy byte buffers (Bytes / Vec), ensuring corrupt or non-UTF-8 torrent files from legacy trackers never panic the engine.

Installation & Deployment

Select the most convenient deployment method for your server or desktop workstation.

CLI ARGUMENTS & RUN MODES BASH
# 1. Launch interactive terminal TUI rstorrent [options] [torrent-files | magnet-uris | urls] # 2. Run as headless server daemon rstorrent --daemon -s ~/.rstorrent/session # 3. Launch without loading .rtorrent.rc rstorrent -n -o directory.default.set=~/Downloads # 4. Override configuration options via command line (-o key=value) rstorrent -o network.port_range.set=50000-50000 -o network.scgi.open_port=127.0.0.1:5000 # 5. Remote control daemon using lightweight rtorrent-tui client rstorrent-tui --connect 127.0.0.1:50051

services: rstorrent: image: ghcr.io/chmuri/rstorrent:latest container_name: rtorrent network_mode: host environment: - RUST_LOG=info volumes: - ~/.rstorrent/session:/session - ~/Downloads:/downloads - ~/.rstorrent/watch:/watch restart: unless-stopped
