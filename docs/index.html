Technologia & Wydajność

Architektura nowej generacji dla BitTorrent

Zaprojektowany od zera w Rust w celu wyeliminowania problemów historycznych klientów: wycieków pamięci, blokad wątków I/O i awarii przy tysiącach aktywnych połączeń.

⚡

Tokio Async & Zero-Segfault

Wielowątkowy asynchroniczny runtime Tokio z nieblokującym I/O dyskowym. Pełne bezpieczeństwo pamięci i odporność na uszkodzenia buforów sieciowych.

🧩

SIMD Rarest-First & Dynamic Endgame

Operacje bitfield O(N/64) z wykorzystaniem sprzętowych instrukcji POPCNT/CLZ. Klasyfikacja prędkości peerów, selekcja najrzadszych części i natychmiastowy globalny broadcast CANCEL w trybie endgame.

🌊

Zero-Copy BufferPool & BDP Tuning

Bezblokowa arena buforów 16 KiB oparta o crossbeam-queue, zero-copy parser Bencode oraz adaptacyjna głębokość kolejki żądań Q w przedziale 4..512 kalibrowana względem RTT i pasma.

🛡️

Wielowątkowy Hash Piece (Rayon)

Kalkulacja sum SHA-1 oraz drzew Merkle SHA-256 (BitTorrent v2) oddelegowana do puli Rayon, dzięki czemu weryfikacja danych nie blokuje wątków asynchronicznych Tokio.

🔌

SCGI, XML-RPC & JSON-RPC

Pełna kompatybilność protokołu SCGI przez gniazda UNIX lub TCP. Płynna integracja z ruTorrent, Flood oraz skryptami ekosystemu rTorrent dzięki obszernej mapie komend.

📡

Natywne gRPC & Terminal TUI

Wydajne API gRPC (Tonic rtorrent.v1) ze strumieniowaniem zdarzeń oraz nowoczesny interfejs TUI w terminalu (Ratatui/Crossterm) z dedykowanym klientem zdalnym rtorrent-tui.

🌐

BitTorrent v1 & v2 (BEP Suite)

Pełne wsparcie dla Kademlia DHT (IPv4/IPv6 BEP 5/32), PEX (BEP 11), Fast Extension (BEP 6), uTP z LEDBAT (BEP 29), szyfrowania MSE/PE, WebSeed oraz torrentów hybrydowych v2.

💻

Wbudowany Web UI (Leptos / Wasm)

Opcjonalny serwer REST + WebSocket oparty o Axum z osadzoną aplikacją SPA napisaną w Rust (Leptos WebAssembly), autoryzacją Bearer token i bezpośrednim podglądem stanu węzła.

Modularny Workspace

16 wyspecjalizowanych skrzyń (crates)

Modularna architektura 16 skrzyń podzielonych na 5 wyspecjalizowanych warstw z rygorystycznymi gwarancjami bezpieczeństwa pamięci.

lt-common
FOUNDATION SAFE
Podstawowe typy danych: parser/serializer Bencode zero-copy, ułamkowy licznik pasma Rate, Bitfield i HashString.
bencode, object, bitfield, rate, hash_string
lt-sys
SYSTEM ISOLATED
Prymitywy systemowe OS: pliki blokad (.lock), bezpieczny wrapper mmap/fadvise, harmonogram i inotify watch directory.
mmap, poll, log_buffer, scheduler, lockfile, watch
lt-crypto
CRYPTO SAFE
Kryptografia P2P: przyspieszany sprzętowo SHA-1, szyfr RC4 z discard-1024, wymiana kluczy Diffie-Hellman 768-bit (MSE/PE).
sha1, rc4, diffie_hellman, pe_crypto
lt-net
TRANSPORT ISOLATED
Warstwa gniazd Tokio TCP/UDP, obsługa dual-stack IPv4/IPv6, grupy dławienia pasma (throttle) i tunele SOCKS5/HTTP proxy.
socket, address, throttle, proxy, dns, poller
lt-protocol
P2P PROTOCOL SAFE
Maszyna stanów protokołu wire: negocjacja MSE/PE, Fast Extension (BEP 6), ut_metadata (BEP 9), PEX (BEP 11) i LTEP (BEP 10).
wire, handshake, extensions, pex, ltep
lt-tracker
TRACKER SAFE
Klient trackerów HTTP/HTTPS oraz UDP (BEP 15) ze scrape, obsługą wielopoziomowych tierów (BEP 12) i backoffem.
http_tracker, udp_tracker, scrape, tiers
lt-dht
DHT KADEMLIA SAFE
Tablica routingu Kademlia Mainline DHT (BEP 5/32), bootstrapping węzłów, tokeny zapytań, sample_infohashes i persystencja.
routing_table, node, bootstrap, token, nodes6
lt-storage
STORAGE ISOLATED
Zarządzanie blokami chunków, pozycjonowany I/O dysku, kolejka HashQueue i szybkie wznawianie sesji (.libtorrent_resume).
memory_chunk, chunk_list, file_list, hash_queue, resume
lt-engine
ENGINE SAFE
Koordynator cyklu życia pobierania: selektor kawałków rarest-first, grupy choking/unchoke, delegator prędkości i dynamic endgame.
download_main, choke_manager, selector, delegator
rt-core
SESSION CORE ISOLATED
Nadzorca sesji klienta: widoki pobierania (main, active, stopped), harmonogram zadań, grupy priorytetów i persystencja stanu.
session_manager, download_list, views, schedule
rt-rpc
COMMAND RPC SAFE
Silnik DSL komend rTorrent (~1000 metod), rejestr wywołań XML-RPC i JSON-RPC 2.0 oraz mostek skryptowy Lua (rtorrent.lua).
command_map, dsl_parser, xmlrpc, jsonrpc, lua_bridge
rt-scgi
SCGI SERVER ISOLATED
Nieblokujący serwer protokołu SCGI na gniazdach UNIX oraz TCP z obsługą keep-alive dla ruTorrent i Flood.
scgi_listener, request_parser, connection_pool
rt-grpc
GRPC TONIC SAFE
Wysokowydajny serwis gRPC rtorrent.v1 (TorrentService, SystemService) ze strumieniowaniem telemetrii i zdarzeń w czasie rzeczywistym.
torrent_service, push_stream, auth_interceptor
rt-tui
TERMINAL TUI SAFE
Natywny interfejs terminalowy (Ratatui/Crossterm): responsywny bufor płótna, баланс klatek, widoki inspekcji i obsługa myszy.
canvas_buffer, widgets, event_loop, view_switcher
rt-tui-client
REMOTE CLIENT SAFE
Samodzielna binarka rtorrent-tui: zdalne sterowanie demonem rtorrent przez gRPC/TLS na dowolnym hoście sieciowym.
grpc_client_bridge, view_model, remote_terminal
rstorrent
APP SUPERVISOR ISOLATED
Główny punkt wejścia CLI, obsługa sygnałów POSIX, supervisor cyklu życia i kompatybilność binarna z symlinkiem rtorrent.
cli_args, supervisor, signal_handler, daemon_mode

Przepływ Danych & Cykl Życia Torrenta

Ścisły nieblokujący potok: asynchroniczny reaktor Tokio dla sieci oraz odizolowane pule wątków Rayon dla operacji dyskowych i weryfikacji sum kontrolnych.

ETAP 01 // METADATA
Parsowanie i Konstrukcja
Bencode parser (lt-common) bez kopiowania przetwarza plik .torrent lub magnet (ut_metadata BEP 9) w TorrentMetadata i obiekt sesji.
ETAP 02 // SWARM PEERING
Odkrywanie i Łączenie
Reaktor lt-net i lt-tracker zgłaszają się do trackerów (HTTP/UDP), a lt-dht przeszukuje tablicę Kademlia w celu pobrania puli peerów.
ETAP 03 // BDP PIPELINING
Transfer Rarest-First
Algorytm SIMD wybiera najrzadsze kawałki, kolejkuje zapytania do peerów z adaptacyjną głębokością Q (4..512) i pobiera bloki 16 KiB.
ETAP 04 // RAYON HASHING
Weryfikacja & Zapis
Kompletny chunk trafia do puli Rayon do weryfikacji SHA-1/256. Po sprawdzeniu zapisywany jest pozycjonowanie na dysku bez blokowania sieci.

Główne Niezmienniki Architektury

Asynchroniczny Reaktor Sieci + Odizolowane I/O Dysku
Reaktor Tokio obsługuje gniazda P2P, DHT i trackery bez blokad. Odczyty/zapisy plików oraz hashowanie SHA-1/256 oddelegowano do Rayon, dzięki czemu wątki Tokio nigdy nie ulegają głodzeniu.
Weryfikowane przez kompilator granice bezpieczeństwa
Rygorystyczna reguła unsafe_code = deny w 9 wyższych skrzyniach. Niskopoziomowy kod unsafe ograniczono wyłącznie do prymitywów lt-sys oraz bezpiecznych adapterów mmap.
Bajtowy model danych Bencode bez paniki UTF-8
Klucze i ciągi bencode przechowywane są jako bufory bajtowe (Bytes / Vec), co uniemożliwia awarię silnika przy nieprawidłowo zakodowanych nazwach plików z zewnętrznych trackerów.

Uruchomienie, Konfiguracja & Integracje

Kompletny podręcznik administratora: parametry startowe, konfiguracja ~/.rtorrent.rc, sterowanie TUI oraz integracja z ruTorrent i Flood.

CLI ARGUMENTS & RUN MODES BASH
# Uruchomienie standardowe w terminalu z interaktywnym TUI rstorrent [opcje] [ścieżki_do_plików_torrent | linki_magnet | adresy_url] # Uruchomienie w tle jako demon systemowy (dla serwerów headless / kontenerów) rstorrent --daemon -s ~/.rstorrent/session # Uruchomienie z pominięciem ładowania pliku .rtorrent.rc rstorrent -n -o directory.default.set=~/Downloads # Nadpisanie parametrów konfiguracyjnych w wierszu poleceń (-o key=value) rstorrent -o network.port_range.set=50000-50000 -o network.scgi.open_port=127.0.0.1:5000 # Zdalne sterowanie demonem rtorrent za pomocą lekkiego klienta rtorrent-tui rstorrent-tui --connect 127.0.0.1:50051
DOCKER COMPOSE DEPLOYMENT YAML
services: rstorrent: image: ghcr.io/chmuri/rstorrent:latest container_name: rtorrent network_mode: host environment: - RUST_LOG=info volumes: - ~/.rstorrent/session:/session - ~/Downloads:/downloads - ~/.rstorrent/watch:/watch restart: unless-stopped
