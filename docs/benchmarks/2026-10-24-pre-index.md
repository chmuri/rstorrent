# Phase 0 baseline — pre-index vs post-index (2026-10-24)

The "before" half of the `DownloadList`/`View` index, captured from the commit
immediately before the index landed. Same synthetic session, same harness,
same host, both release builds.

- **before**: `5c2e7d7c` (`6165764a^`, no hash index)
- **after**: `0a4121aa` (index + focus revert + metadata guard)
- **harness**: `d15eb368`

## Method

```bash
git worktree add --detach /tmp/opencode/rstorrent-baseline 5c2e7d7c
(cd /tmp/opencode/rstorrent-baseline && \
  CARGO_TARGET_DIR=/home/chmuri/git/rstorrent/target cargo build --release -p rstorrent)

scripts/bench/run_all.sh --count 14000 --lookups 5000 --multicall 10 \
  --no-build --bin /home/chmuri/git/rstorrent/target/release/rstorrent
```

Session: 14,000 synthetic paused torrents, no payload, no trackers.
Host: 8 cores, ext4, `nofile` 1,048,576, `rstorrent 0.13.0`, Python 3.12.3.
Both runs used the same generator seed and the same `rustc` profile.

## Results at 14,000 torrents

| Metric | before `5c2e7d7c` | after `0a4121aa` | change |
|---|---:|---:|---:|
| startup `full_s` | **157.90 s** | **1.375 s** | **115x faster** |
| peak RSS | 129.7 MB | 134.3 MB | +3.5% |
| `d.hash` p50 | 0.463 ms | 0.070 ms | 6.6x |
| `d.hash` p99 | 1.038 ms | 0.165 ms | 6.3x |
| `d.multicall2` p50 (14k x 12) | **47,096 ms** | **217 ms** | **217x** |
| `d.multicall2` p95 | 49,745 ms | 258 ms | 193x |
| threads / FDs at rest | 11 / 12 | 11 / 12 | unchanged |

## Reading

- **Restore was quadratic and is now linear.** 158 s to restore 14k paused
  torrents meant the daemon was unusable for over two minutes after a restart;
  it now finishes in 1.4 s, and the 1k/5k/14k scaling in
  `2026-10-24-scaling.md` shows no remaining quadratic term.
- **`d.multicall2` was the worst offender, not startup.** Each of the 12
  columns resolves a download target, and every resolution was a linear scan:
  14k x 12 x 14k. A single Flood poll took ~47 s before and 217 ms after.
  This is why Phase 7 (hoist command parsing) still matters, but it is no
  longer O(n^2).
- **Lookup cost is now independent of N.** The remaining p99 difference
  (1.0 ms -> 0.17 ms) is the scan disappearing; at 1k the post-index p99 is the
  same 0.17 ms, so it is flat rather than merely faster.
- **Memory is essentially unchanged** (+4.6 MB for the two index maps at 14k,
  ~330 bytes/torrent). The win is time, not space.

Absolute numbers are host-specific. The ratio is the artifact to keep: if a
later phase regresses `startup.full_s` or `multicall.p50_ms` by more than 50%
against this table, it needs an explanation in its PR.
